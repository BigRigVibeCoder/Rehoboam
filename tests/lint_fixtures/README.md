# Lint fixtures: positive controls (SPR-001)

Each fixture plants one violation that a gate must catch. `bin/check_all.sh` runs every gate on the
real repository (it must pass) and on each fixture (it must FAIL, printing that gate's own diagnostic,
via `run "<name>" "fail:<text>"`). If a control ever passes, its gate has stopped working. The licence
ledger is not a gate (ADR-0021 as amended 2026-10-16, personal-use mode); its control must succeed and
list the planted licence (`pass:<text>`).

Fixture workspaces carry their own `[workspace]` table and sit under the root `Cargo.toml`
`exclude`, so they never join the Rehoboam workspace. Nothing here is built except the compile-fail
cases (into `target/lint-fixtures/`). Everything runs offline; the git-source and clippy-float controls are rendered into
`target/rendered-fixtures/` and fetches its dependency from a local `file://` repository.

**What the textual rules flag, and what they do not scan** (VER-SPR-011-TEST GAP-4, GAP-6; BCK-002
A-49). The `process`, `file-io`, `file-clock` and `env` rules of `bin/lint_forbidden.py` match text,
conservatively: a crate's own module named `process` (`process::f()`), its own module named `fs`
(`fs::foo`), or its own accessor named `.created()` or `.mtime()` is flagged like the std item. That
is accepted: such a line carries `// LINT-ALLOW(forbidden-api): <reason>`, and the gate counts and
prints every escape, so review sees each one. These rules apply to `src/` and `build.rs` only. The
`tests/` of plane-A crates are trusted, not scanned for them: a test may read its golden files, an
override from the environment, or name a temporary directory by process id, and tests never link
into the engine. The `spec-loader` rule (A-47) retired with BCK-002 A-51 (SPR-013): `rh-registry` keeps pure parsers (`parse_specs`, `parse_registry_system_ids`), the host reads the files (`rh_manifest::specs`), and `rh-registry` left `FILE_IO_CRATES`, so a spec read anywhere in its `src/` is a `file-io` violation.

Since SPR-003 GAP-9, every plane-A crate in the `arch/` and `compile_fail/plane_a_names_plane_*` fixtures declares `[lints] workspace = true` (each fixture root has a `[workspace.lints]` table), so each control fails only for the rule it plants.

Each compile-fail case also passes `bin/lint_arch.py` (its graph has no edge), which shows the failure
is the language barrier: plane-A code can reach a plane-B or plane-C type only through a dependency
edge, and `arch/plane_a_to_b/` and `arch/plane_a_to_c/` show the lint rejects that edge. The unit tests in `python/tests/` check each
rule in more detail, including the cases a gate must not flag.
