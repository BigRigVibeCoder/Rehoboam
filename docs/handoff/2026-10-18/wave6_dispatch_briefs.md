## What every Developer is told (lessons of 2026-10-18)

1. Read `HANDOFF.md`, `CLAUDE.md`, `AGENTS.md`, GOV-009, GOV-010, GOV-011, then the plan and everything it names as binding.
2. Branch from `main` at dispatch time; first commit is the draft PR with the template filled, including the `Agent:` line.
3. **A task named "move" or "remove" is a move.** SPR-015 T-01 copied a spec and left the draft, and CI caught it. Run the lint and the oracle that name the removal before pushing.
4. **Baselines, goldens, locks and skeletons are regenerated by their tools in the one `[C3] [perf-baseline]` commit at the end**, never typed and never moved to make a gate pass. A cost regression is diagnosed first (SPR-015's +62% quiet-instant cost is the example).
5. **Run the full `bin/check_all.sh` locally** (`uv sync --frozen --project python` first; one cargo-building run at a time per machine) before asking for an audit. No report, no pass.
6. **Stop at each checkpoint the plan names.** The Tester's interim pass is required before the next task lands. Pushing past it was SPR-015's second failure.
7. Stage files by explicit path. Never `git add -A` on a directory. Never commit `CODEX/00_INDEX/MANIFEST.yaml`, `artifacts/`, `target/` or `python/.venv/`.
8. Commits are `type(SPR-NNN): T-NN description [Cn]` with `Why:`, `What:`, `Refs:` and your own tool's attribution. Do not push to `main`; never force-push or rebase a pushed branch.
9. Merge `main` into your branch by `git merge origin/main`. `bin/check_all.sh` and `python/tests/test_check_all_inventory.py` conflict often: resolve by gate name, then run `python -I bin/check_all_selftest.py inventory` and expect "both ways".
