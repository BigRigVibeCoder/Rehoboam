# ADR-0004 — Raster + region graph + shared settlement generator

**Status:** Proposed · **Date:** 2026-10-15

## Context

The draft ran society on 16×16 grid chunks and gave no account of street-level content. Politics, markets, armies and contagion follow provinces and routes. The 3D client needs deterministic towns that agree with the simulation.

## Decision

Four nested layers:

1. **Raster.** Terrain, climate, biome and physical hazards. Laplacian diffusion is allowed only here.
2. **Region graph.** 300–2,000 Voronoi provinces with typed routes, generated by an Azgaar-FMG-style reimplementation (MIT).
3. **Abstract settlements.**
4. **Settlement plans.** Wards, streets and plots, generated lazily and deterministically by a shared Rust crate, `rh-worldgen`, that both the server and the Godot client link. Plots bind to households and businesses. Simulation events persist as overrides.

## Alternatives considered

| Option | Why not |
|---|---|
| Grid chunks for society | Arbitrary with respect to geography. |
| Client-only town generation | Diverges from the simulation: errands become fake. |
| Watabou MFCG code | GPL-3.0. Reimplement the ideas instead. |

## Consequences

- One generator, versioned, is used everywhere.
- Plans grow incrementally, never through a global re-solve.
- Generators must be deterministic and versioned (R3D-2).

## Revisit when

- A street-scale simulation (C2 household micro-economy) needs plot-level state for every settlement, not only lazily.
