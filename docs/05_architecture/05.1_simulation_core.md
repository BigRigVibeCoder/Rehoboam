# 05.1 — Simulation Core

*Status: Draft v1.0 (2026-10-15). Sources: R01, R03, R09, R10. Decisions: ADR-0001…0007, 0020.*

---

## 1. Scope

`rh-core` and the system crates own all authoritative world state and its evolution. That covers:

- terrain and fields;
- the region graph;
- the ledger (every person);
- pop aggregates;
- named actors;
- polities, armies and markets;
- the scheduler, RNG and invariants;
- event emission.

`rh-core` has **no I/O**. Every host (CLI, server, Python wheel, GDExtension) wraps the same library.

## 2. The `SystemModel` contract

Every simulation system implements one trait. This is the main mechanism for success claim S4: a new system or fidelity level is a new implementation of this trait plus registry entries, and nothing else needs to change.

```rust
/// Illustrative. The final signatures will be fixed in rh-core during P0.
pub trait SystemModel: Send + Sync {
    /// Stable identity: "M2.demography", fidelity "F1", semver of the model.
    fn descriptor(&self) -> SystemDescriptor;

    /// Tables/columns this system reads and writes (checked against the schedule
    /// for write conflicts at startup; two systems may not write the same column
    /// in the same phase).
    fn access(&self) -> AccessSpec;

    /// Which pulses this system runs on, and in which phase.
    fn schedule(&self) -> Vec<PulseBinding>;   // e.g. [(Month, Phase::Vital), (Day, Phase::Epidemic, when=Active)]

    /// Parameter schema + bounds (exported to the Registry / JSON Schema).
    fn params_schema(&self) -> ParamSchema;

    /// Deterministic update. `ctx` provides keyed RNG, the event bus and clocks.
    fn step(&self, pulse: Pulse, world: &mut WorldTables, ctx: &mut StepCtx) -> Result<(), SimError>;

    /// Conservation and sanity invariants, run after step in debug/CI builds.
    fn invariants(&self, world: &WorldTables) -> Vec<InvariantResult>;

    /// Aggregate statistics this model promises to reproduce (used for
    /// F(n+1) ↔ F(n) consistency tests and stylized-fact validation).
    fn declared_aggregates(&self) -> Vec<AggregateSpec>;
}
```

**Rules for systems.**

1. Systems never call each other. They communicate through state tables, and through events consumed on the next phase or pulse.
2. All randomness comes from `ctx.rng(purpose, entity, k)`. There is no other RNG.
3. Any quantity that crosses a decision threshold is an integer or fixed-point value (§6).
4. Each system declares its events in the Registry, with roles, act classes and default tellability.

**Fidelity consistency contract.** A model at F(n+1) must reproduce the `declared_aggregates` of F(n), for example region population trajectories, mortality-crisis frequency and price variance, within declared tolerance across the reference ensemble. Otherwise it must carry a written exemption in its ADR. This is the multi-resolution-modelling consistency criterion turned into CI (R01 §3).

**Coexisting fidelities.** Fidelity is chosen per world, and can differ per region. For example, a focus region can run demography F2 while the hinterland runs F0. The interface is a *conservation handshake* at region boundaries: migration, trade and contagion flows are exchanged as counts.

## 4. Time and scheduling

### 4.1 Sim-time
- `SimTime = u64` minutes since world epoch. The calendar (year length, months, seasons) is a manifest parameter. The default is 12 × 30 = 360 days, which keeps arithmetic simple; a realistic 365-day calendar is optional.
- **Pulses:** `Year`, `Season`, `Month`, `Day`, `Hour`, plus `Realtime` inside the bubble only. Each system binds to pulses (§2).
- **Adaptive daily stepping.** M5, M8 and siege mechanics request `Day` pulses only for regions, armies and sieges that are *active*. Activity is decided deterministically at the preceding coarser pulse.

### 4.2 Phase order inside one instant (part of the determinism contract)

| # | Phase | Contents |
|---|---|---|
| 1 | `Inputs` | Apply journaled inputs whose timestamp falls in this instant: player actions, accepted LLM choices. |
| 2 | `Environment` | Climate, seasons, fields (M3, physical rasters). |
| 3 | `Production` | Agriculture yield, economy production (M3/M4). |
| 4 | `Exchange` | Prices, trade, wages, taxes (M4). |
| 5 | `Vital` | Births, deaths, marriages, migration (M2/S3). |
| 6 | `Contagion` | SEIRS steps, testing, fear (M5). |
| 7 | `Polity` | Legitimacy, elite dynamics, instability, revolts (M6). |
| 8 | `Military` | Campaign moves, battles, sieges (M8). |
| 9 | `Agenda` | Named-actor decisions due at or before this instant, in order (`time`, `phase`, `entity_id`, `seq`) (rh-minds). |
| 10 | `Culture` | Belief, ideology and technology diffusion (S1/S2). |
| 11 | `Bookkeeping` | Invariants, aggregates, the monthly state hash, keyframe trigger. |

Events emitted in phase *k* are visible to phases > *k* in the same instant only through state tables. The sifter consumes events strictly in emission order.

### 4.3 Named-actor agenda
- A binary-heap discrete-event queue keyed `(time, phase, entity_id, seq)`.
- Each actor carries per-decision-type polling intervals (CK3-style, 1–12 months) plus **interrupts**. An interrupt is an event perceived through a channel that is above the actor's salience threshold, and it schedules an immediate re-evaluation.
- In the bubble, embodied actors may re-evaluate at 1–5 Hz. Those evaluations are *non-authoritative elaborations* unless they produce material events (`05.2` §5).

### 4.4 Time controls
- Speed bands (sim-time per wall-second): Live · 1 h/s · 1 d/s · 1 wk/s · 1 mo/s · 1 yr/s · 1 decade/s · **MAX**.
- **Run-until:** a date, a predicate over aggregates (`famine(region) OR war(realm)`), or `next_match(salience ≥ θ)`.
- Speed bands change **only** how often a frame is published and how far `advance_until` goes per wall-clock interval. **They never change the simulation.**

| Data | Structure | Size @1M persons | Notes |
|---|---|---|---|

## 6. Determinism contract (ADR-0006)

1. **History function.** `history = f(engine_build, registry_version, manifest_hash, seed, input_journal)`.
2. **Keyed RNG.** Every draw is `u = H(world_seed, branch_salt(t), system_id, purpose, entity_id, t, k)`.
   - `H` is a counter-based generator: Philox-4x64 or ChaCha8 with `set_stream`/`set_word_pos`; SplitMix64 or xxh3 for cheap scalar hashes.
   - A new system never perturbs existing ones, and draws are order-independent and parallel-safe.
3. **Vendored samplers.** Binomial (BTPE plus inversion for small n·p), Poisson (PTRS), normal (ziggurat with fixed tables), Beta and Gamma. Distribution crates are never pulled in, so that an upgrade cannot change values. Golden vectors are kept for each sampler.
4. **Numerics.**
   - Integers or fixed-point for counts, money (i64 minor units), loyalty and psychology (Q8.8 / Q16.16) and timers.
   - Floats only in fields and continuous dynamics, evaluated in fixed order with pure-Rust `libm`.
   - No `mul_add`, no fast-math. C dependencies are built with `-ffp-contract=off`.
   - Values are quantised to integers at macro boundaries before they drive decisions.
5. **Iteration and parallelism.** No `HashMap` or `HashSet` iteration in authoritative paths: use `BTreeMap`, `IndexMap` or sorted `Vec`. Rayon only with fixed chunking (65,536 elements). Reductions combine per-chunk results in chunk order.
6. **Hashing.** An xxh3-64 state hash every sim-month, over a canonical serialisation of the authoritative tables, written to `state_hashes`.
7. **Unsynced guard.** Read-only consumers (renderer frames, console queries, LLM context builders) run under a guard that asserts the state hash is unchanged, in the manner of OpenRA's `RunUnsynced` (R03 §4).
8. **Golden runs.** CI replays reference worlds (`worlds/`) for 1,000 years and compares hashes every sim-year: on Linux x86-64 on every PR, and on Windows x86-64 and macOS ARM nightly.
   - **Guarantee level 1:** bit-exact on the same binary, OS family and CPU architecture.
   - **Level 2 (goal):** bit-exact across platforms.
   - If level 2 is not achieved, cross-platform sharing falls back to keyframes.
9. **Branch salts and common random numbers.**
   - The canonical timeline uses salt 0.
   - A Foresight rollout k uses salt k for all `t ≥ fork_tick`, so history before the fork is untouched.
   - Evaluating an intervention runs the *same salts* with and without the intervention (common random numbers), so the paired difference has far lower variance (`05.3` §7).

## 7. Lifetime, compaction and genealogy

- About 35–40M people live and die over 1,000 years at a stable 1M population. Dead rows are compacted unless any of these holds:
  - the person is **pinned**;
  - they belong to a **tracked lineage** (ancestors of any named or pinned person);
  - they are referenced by a retained event.
- Compacted dead are folded into `(region, decade, cause, class, age band)` death counts.
- Lineage links of tracked lineages are kept forever in a `lineage` table of `(id, mother, father, birth, death, region)`, at ~40 B each.

## 8. Drama couplings to implement first (R09)

1. **Famine → unrest → succession crisis.** Two bad harvests (M3) send grain prices up ×3–5 (M4). Entitlement collapses and infants and the old die (M2). Mass mobilisation potential and fiscal stress rise (M6). The regicide hazard rises (M7). There is a ~0.3 probability the heir is a child, which brings a regency, then civil war, and armies eat the grain that is left (M8).
2. **Plague → paranoia → purge → labour revolt.** An outbreak (M5) raises fear, which brings multi-wave epidemics. Scapegoats are drawn from the out-group (S1), and purges cut legitimacy. Wages rise while rents fall, elite income is squeezed, wage freezes follow, and a Granovetter cascade produces revolt.
3. **Hive detection spiral (modern).** At low prevalence, most positive tests are false. Innocents are detained, legitimacy falls and paranoia rises. People avoid tests and falsify preferences. Covert spread accelerates, PPV then improves, and "the purges were right" becomes the political story.
4. **Elite overproduction.** Prosperity leads to elite growth, then intra-elite feuds and a 40–60-year violence wave.
5. **Dragon age.** Livestock boom, then a dragon population boom, then raids and famine pockets, then the prestige of hunting dragons.

Each coupling is tested as a **scenario test**: a seeded world where the chain must be *possible* (it appears in ≥ x% of an ensemble) and *not forced* (it is absent in ≥ y%).

## 9. Invariants (minimum set)

- Population conservation: births − deaths ± migration equals Δ ledger alive count, per region per month.
- Food, coin and pathogen compartments: the sum across regions and markets is conserved, apart from declared sources and sinks.
- No negative compartments, stocks or counts.
- Genealogy is acyclic, and birth tick is after each parent's birth tick plus a minimum age.
- Every alive named actor has an alive ledger row. Ledger alive implies a `death_tick` of None.
- Exclusive relations hold: one ruler per title, one location per person.

## 10. Python prototyping lane

New models may first be prototyped in Python (NumPy/Numba, marimo notebooks), against the same Registry parameters and a shared fixture world exported through `rh-py`. A model is promoted to Rust only once it passes the stylized-fact bands. The Rust port must then match the prototype's declared aggregates within tolerance (a statistical-equivalence test, not a bitwise one). This keeps fast agent iteration without giving up the determinism and performance of the core.
