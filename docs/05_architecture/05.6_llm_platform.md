# 05.6 — LLM Platform (Gateway, Models, Structured Generation, Safety)

*Status: Draft v1.0 (2026-10-15). Sources: R04, R05, R08. Decisions: ADR-0011. All model names and prices are as of Oct 2026 (R05 §1, §7). Re-verify them before locking anything in, because this landscape changes monthly.*

---

## 1. Role and boundaries

The **LLM Gateway** (`python/rehoboam_llm`) is the only component that talks to language models. It has four properties:

- **Typed jobs.** Every call is a job kind with an input schema, an output schema, a budget and a routing policy.
- **Journaled.** Requests and responses are logged with model ID, weights hash (local) or provider version, prompt hash, latency, tokens and cost. Outputs that affect state are appended to the simulation's **input journal** (DET-7).
- **Replaceable.** Providers sit behind one adapter interface, a thin in-house layer of about 300 lines. The LiteLLM SDK is optional, pinned with hashes, and the LiteLLM *proxy* is avoided because of its 2026 advisories (R05 §7).
- **Never authoritative.** No job holds a write handle on world state. The simulation validates every output it receives.

## 4. Structured generation rules

1. **Reason, then constrain.** Allow a thinking block or a free-text `reasoning` field first, then emit the constrained object (CRANE).
2. **Enums from live registries**: culture IDs, legal actions, belief IDs. Models never invent IDs.
3. **Discriminated unions** with a `kind` constant. No `Dict[str, Any]`, no `additionalProperties: true`. Keep optional fields few, because Anthropic caps strict-mode optional and union parameters.
4. **Numeric ranges live in validators**, not schemas, because provider and grammar engine support for them is partial.
5. **Every response is checked:**
   - `stop_reason ∈ {max_tokens, refusal}` is a failure;
   - enums are compared case-insensitively;
   - Pydantic and the semantic validators run;
   - at most 3 repair rounds with machine-readable errors, then fall back.
6. **Truncation guard.** Set `max_tokens` with headroom. Large outputs are produced in parts (per chapter or scene).

## 5. Grounded dialogue (summary; details in `05.3` §8)

- **Context = belief DB only.** The prompt contains the persona card, belief texts above an activation threshold for the topic, relationship summaries, emotional state and recent turns. **World truth never enters the prompt.**
- **Plan, then realise.** The simulation decides `SpeechPlan`; the model only realises it in the character's voice.
- **Claim check.** Every reply is decomposed into claims. A claim not in `belief_ids ∪ planned_lies` triggers a regenerate (up to 2 times), then a template fallback.
- **Prefix caching is mandatory.** The stable prefix is world rules → persona → belief snapshot, and only the new turn is appended. llama.cpp slot save and restore persists per-NPC KV state. Hybrid models (Qwen3.5 Gated-DeltaNet) and sliding-window models (Gemma) need context-checkpoint tuning (`-cms`); measure TTFT for each model before committing.

## 6. Safety and prompt injection

- Player text is always **quoted data**. It never sits in the same message as outcome-defining instructions (the dual-LLM / action-selector pattern).
- Models that consume player text have **no tools and no state access**.
- Outputs are **labels from closed schemas**, never numbers or verdicts. The simulation computes every effect.
- Effects are **bounded**: per-whisper caps, habituation, per-target-season caps. Detected meta-instructions are **penalised in-world**: Paranoia rises and the target forms an "uncanny voice" memory.
- A **red-team corpus** runs in CI against every job that consumes player text: injections, master-key tokens, and the 40-technique persuasion taxonomy.
- **Content policy.** Grim historical content (purges, plagues, witch-hunts) is the point of the simulation. Narration prompts frame it as history and avoid gratuitous detail. Refusals are logged and routed to an alternative provider.

## 7. Evaluations (gate before choosing any model)

| Eval | Content | Metric | Gate |
|---|---|---|---|
| **RP-200** | 200 dialogue scenarios over our own belief store: concealment, lies, gossip, unknown-fact refusal, multi-turn drift (≥ 10 turns), player jailbreaks | Leak rate, unsupported-claim rate, persona adherence, TTFT | Leak = 0 on concealment items; unsupported claims < 2%; TTFT p95 < 0.5 s on the reference GPU |
| **ARG-300** | 300 whisper texts with gold `ArgumentFrame`s, including 60 adversarial | Field-level F1; meta-instruction recall | F1 ≥ 0.85; meta recall ≥ 0.95 |
| **INTENT-100** | 100 world prompts → expected template and key overrides | Exact template match; validator pass rate after repair | ≥ 90% / ≥ 98% |
| **NOVEL-20** | 20 fixed epochs × configurations | Contradictions, coverage, slop, cross-book similarity, judge Elo, your blind ratings | 0 T0/T1 contradictions |

Evals are re-run on every model or prompt change. Results are stored per model ID, so routing choices stay evidence-based.

## 8. Cost governance

- Each job declares a budget (tokens and $). The gateway enforces per-run and per-day ceilings and reports cost per artefact.
- Indicative costs from R05 and R08:

  | Item | Cost |
  |---|---|
  | World compile | < $0.10 |
  | 100k-word novel, recommended config with batch + cache | ~$28 |
  | 120-page screenplay | ~$15 |
  | 10-episode audio-drama script | ~$19 |

- The rate of pivotal consults is capped per simulated year (default ≤ 20/yr per world). They are pre-batched before MAX-speed runs, so LLM latency never stalls the simulation.
