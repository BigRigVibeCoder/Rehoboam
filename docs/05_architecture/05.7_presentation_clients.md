# 05.7 — Presentation: the Local Saga Reader, the Text Time-Machine and the 2D Diorama

*Status: Draft v1.1 (2026-10-15). Sources: R06, R10, R01, R11. Decisions: ADR-0016 (console), 0018 (3D client), 0023 (wire protocol), 0024, 0025.*

*v1.3 (2026-10-16), **ADR-0035:** **no custom 3D.** Every visual is 2D: Kenney CC0 tile packs and glyph layers (deck.gl; rot.js as a reference). Part B (Godot) is **cut** and kept only for history. **The engine only engines:** every presentation surface is a downstream consumer of the World Stream that never calls back into the engine. The local Web Graphic Novel / Storyboard Reader (Part D, `05.11` §8) is the only presentation surface for sagas; `rh-tui` stays the keyboard Time-Machine; the 2D diorama (Part C) lives in `console/`. The web console of Part A is re-scoped accordingly.*

*v1.2 change: **art phase 1 is a lo-fi glyph client inside the console (Part C, ADR-0029)**; the Godot 3D client (Part B) becomes the optional art phase 2.*

*v1.1 changes: Cultivator and Oracle console modes; modalities named rather than numbered; T3 exists only at Live speed, with hydrate/dehydrate hysteresis; Spectacle defined; drop-in is read-only and acting in the past forks.*

## Part A — The Console (Millenary Time-Machine, Oracle in 2D, Narrative Compiler front end, inspection)

> **Re-scoped by ADR-0035.** The screens below are a design catalogue, not one app. Scrubbing, the causal inspector, person and place pages and the chronicle go to the local saga reader (Part D, P3) and to `rh-tui` (P2). Genesis and Compiler go with the world compiler (P4). Oracle, Foresight and the Cultivator/Oracle modes arrive with P4 in `rh-tui`, and reach the 2D travel map in P5. There is no separate TypeScript console: `console/` holds only the P5 diorama. None of these surfaces is served by `rh-server` (ADR-0035 §6): each is a separate consumer that reads the stream and sends journaled inputs through IF-0.

### A1. Technology
- **Stack (earlier design; ADR-0035 re-homes it):** reading views are static pages from `python/rehoboam_reader`; interactive views are `rh-tui`; the map views are the P5 diorama in `console/` (TypeScript + Vite). None is served by `rh-server`; they talk to its IF-0 control and stream endpoint only.
  - Map: **deck.gl 9.x** with `OrthographicView` and binary/Arrow attributes.
  - Causal graph: **Sigma.js 4** (WebGL, thousands of nodes).
  - Small explanation subgraphs: dagre (MIT) or Graphviz-WASM.
  - Timeline: a custom canvas.
  - Data arrives as Arrow IPC.
- **Packaging:** browser first. Tauri 2 is optional on Windows and macOS. On Linux use Electron or a browser until WebKitGTK WebGL performance has been verified (R10 §6).
- **Analytics and calibration:** marimo notebooks over DuckDB read-only views. Rerun for debugging spatial and time-series data.

### A2. Console modes and screens

The console runs in one of two **modes** (`05.3` §6.2), shown permanently in the header bar:

| Mode | What every screen shows | Oracle verbs |
|---|---|---|
| **Cultivator** | The true plane-A state: secrets, hive membership, every causal edge | Disabled by default. If enabled, every verb is journaled as `omniscient` and the timeline is excluded from Oracle-mode statistics |
| **Oracle** | Only what the Oracle entity knows. Map, inspector, chronicle, Person pages and Foresight are all filtered through its belief store; unknown events are absent, not greyed | Enabled |

Switching mode is itself journaled. The Time-Machine, Chronicle and Compiler work in both modes.

| Screen | Purpose | Key elements |
|---|---|---|
| **Genesis** | Create or load worlds | Manifest editor (YAML with schema hints), prompt-to-world (P4), mapping table, liveness-gate result, calibration log, certification report (stylized-fact bands, tail fits; certified or uncertified), gap reports |
| **Time-Machine** | Run and watch history | Speed bands, run-until builder, auto-pause thresholds, *overview strip* (1,000-year density and drama), *detail lanes* (one lane per dynasty or faction, beats as spans), keyframe markers, fork button |
| **Map** | Spatial state at the cursor tick | Regions and polities, routes, armies, epidemics (S/E/I/R heat), famine and price overlays, rasters, settlements; LoD aggregation |
| **Causal Inspector** | "Why did this happen?" In Oracle mode, only edges the Oracle knows. | x = time, y = lanes per actor. Typed edges (contingent, motivated_by, relayed_knowledge…) with legend and filters. Anchored values shown on each node. Significance components. "Expand ancestors / descendants". "Explain" (LLM, provenance-tagged, optional) |
| **Person / Place** | Inhabitable detail | Ledger row, genealogy tree, life events, beliefs (if named), opinions, pinned facts, settlement history |
| **Chronicle** | Read history | Annals, Chronicle, In-world documents. Every sentence links to its events |
| **Oracle (2D)** | Influence (Oracle mode) | Oracle token and travel ETA, Foresight pool, verbs (Whisper, Pierce, Omen, Ward), whisper composer with **parse preview**, consequence tracker |
| **Foresight** | Prophecy | Predicate builder (sifter grammar), N and horizon, P ± CI (rollouts start from a belief-resampled state in Oracle mode, the true state in Cultivator mode), failure-path clusters, intervention A/B with common random numbers, reliability diagram |
| **Ratings** | MOE instrumentation | 1–5 rating on every auto-pause and chronicle excerpt; notes; personal preference model status |
| **Compiler** | Narrative jobs | Form, style card, proposals, cost estimate, progress, QA report, exports |

### A3. Interaction contracts
- **Scrub** reads only the chronicle and regional aggregates. It must respond in < 100 ms (MOP-3).
- **Drop in** means keyframe + replay, with a progress bar. Its target is ≤ 10 s (MOP-4). A drop-in to the past is **read-only** (passive).
- **Acting in the past** (any material input at t < head) automatically **forks** a new timeline from that point (ADR-0025). The canonical timeline is never rewritten, and the fork appears as a branch in the Time-Machine lanes.
- Every number and sentence is clickable through to its provenance.

## Part C — The 2D Diorama (P5; ADR-0029, ADR-0035)

Minimal, Dwarf Fortress–style: CP437 glyphs **and Kenney CC0 2D tiles**, people as glyphs or tiles, colour from palette indices. It lives in `console/`, the only TypeScript app left, and reads the stream (IF-4 frames) without calling back into the engine. **No custom 3D asset is ever made** (ADR-0035).

### C1. Rendering
- **`GlyphGridLayer`** for deck.gl 9.x:
  - instanced quads (a background block plus a foreground glyph);
  - a CP437 atlas with nearest-neighbour filtering;
  - per-cell glyph, foreground and background palette indices taken straight from IF-4 columns;
  - redrawn only on change.

  It starts from the stock `IconLayer` (pre-packed atlas, `mask` tinting). The single-batch shader pattern is ported from wglt (MIT, code only).
- **Target:** ≥ 10k cells at 60 FPS in a browser on a laptop iGPU. A 12×18 font on 1080p gives 160×60 = 9,600 cells.
- **Fallbacks:** beamterm (MIT, one instanced draw) or PixiJS, behind the same layer interface.

### C2. Zoom levels and data sources
| Zoom | Shows | Source |
|---|---|---|
| Z0 world / travel map | Terrain glyphs, polity background colour, settlements by size class, routes as box-drawing lines, armies, epidemics, famine overlays | `map.glyph_tiles(z, x, y, tick)` (deck.gl `TileLayer`), built from regional aggregates and the chronicle, so scrubbing stays < 100 ms (MOP-3) |
| Z1 settlement | Plots, streets, walls, building classes; crowds as ░▒▓ density per block | The server rasterises the shared `rh-worldgen` settlement plan; chunks are cached by settlement × generator version × override epoch |
| Z2 street / room (diorama view; walking it is Later) | Individual people as glyphs (`appearance` picks the glyph, `status_mask` the colour, `verb` an accent); the player's `@` | `bubble.subscribe(center, radius, lod_profile: "glyph")`. Positions snap to cells; when several people share a cell, one is shown (named first) with a count badge; no interpolation |

### C3. Modalities
- **Living Diorama.** A 2D camera director with slow cuts, plus replay mode. Candidate vantages are pre-computed per settlement and region (market, gate, river bend, ramparts, temple steps); each is scored as salience of nearby live events × visual interest (crowd density, weather, time of day) × novelty, and the director changes vantage on a slow cadence (minutes), favouring stable shots in wallpaper mode (R3D-7).
- **Settlement growth view** (P5.11). A SimCity-style time-lapse of one settlement's plan growing over centuries, with the chronicle's overrides (fires, new keeps), scrubbable on the causal timeline.
- **2D travel map** (P7.1, moved to P5). Z0 with time compression; Oracle verbs from the map once P4 has them.
  - **Windows:** the page runs as a **Lively web wallpaper** (Lively is GPL-3.0 and runs as a separate app). Lively suspends the page when it is covered and fires `livelyWallpaperPlaybackChanged`. The page then unsubscribes from the bubble and stops its loop. Rendering is capped at 10–15 FPS.
  - **macOS:** Plash.
- **Street-level Inhabitant (Later, optional; ADR-0035).** A Caves of Qud–style layout: the glyph view plus a DOM side panel in Unscii-16 with a location line, message log and dialogue.
  - **Movement:** the `@` moves by `player.act(MOVE)`, a journaled material input. Its new position arrives in the next frame; the client never predicts it.
  - **Look mode:** `entity.person`, which writes the facts ledger (plane B).
  - **Dialogue:** `dialogue.start/say`, with lines shown with a typewriter effect; you pick numbered options or type freely.
- **Time-Machine.** An "ASCII skin" toggle on the Map screen.

### C4. Glyph packs (per era and culture)
- **Format:** an atlas PNG, a palette, and JSON keyed by **Registry IDs** (terrain, building type, occupation, vehicle, creature, status). Each key maps to a glyph, foreground and background colours, and variants.
- **Variants** are chosen by eligible-set rendezvous hashing over `appearance`, exactly as in B4. The client never uses random numbers.
- **Overrides:** culture overrides sit on top of the era pack.
- **CI:** a lint fails if any Registry presentation key is unmapped.
- **v1 packs:**
  - `medieval`, from **Bitlands** (DragonDePlatino, CC-BY 4.0: a full CP437 12×18 sheet plus about 500 tintable creature sprites, and map, building, item and plant sheets);
  - `ancient`, for `uz_job`;
  - Kenney 1-Bit (CC0) for later modern extras.
- **Kenney CC0 tile packs** (P5.10): a tile-pack format beside the glyph packs, keyed by the same Registry IDs and drawn by the same layer; the CC0 licence text is archived on download (`14` §S).
- **Text:** Unscii-8/16 (PD/CC0); never `unscii-16-full`, which is GPL.
- **Cost:** about 2–4 days per era pack.

| **Watabou's Medieval Fantasy City Generator** | Settlement layouts from seeds, as a presentation-only source for the diorama and the growth view, compared with `rh-worldgen` plans | P5 candidate (WP P5.12) | GPL-3.0; allowed in personal-use mode (ADR-0021 as amended), run out of process; never authoritative |

### C5. Rules
- **The client decides nothing.** It computes no FOV, pathing, visibility or randomness. Oracle-mode filtering happens on the server. A lint and frame-equality tests enforce this (V-R3D-11).
- **Licences (ADR-0021).**
  - Use only allow-listed assets, with attribution tracked (Bitlands).
  - No DawnLike (conflicting licence statements), no int10h fonts (CC BY-SA), no unlicensed Dwarf Fortress community tilesets, and no fonts bundled inside libraries (wglt, libtcod, bracket-lib).
  - No Dwarf Fortress branding.
- **`rh-tui`, the phase-1 harness (ADR-0030; previously optional).** A ratatui + crossterm (MIT) terminal client that reads the World Stream (`05.10`) with its own cursor and shares the Rust decoders. Until G2 it is the only interactive view; its status line always shows the tip, the pace, your cursor and the lag. Its panels are the chronicle feed, a query prompt with a causal-ancestor tree, an ASCII/CP437 map keyed by the same Registry glyph keys as the glyph packs, a keyboard Time-Machine, engine vitals and the G2 rating form. After G2 it stays as the contract-test client and for headless or SSH use.

## Part D — The Local Saga Reader (P2–P3; ADR-0035, `05.11` §8)

The local Web Graphic Novel / Storyboard Reader is **the only presentation surface for sagas**.
- **Static pages** generated by `python/rehoboam_reader` from the sealed chronicle and the chronicle pipeline's outputs, opened from a local folder. No server, no network, and no call to the engine.
- **P2 (reader v0):** episodes, the audio chapter player, the episode text with every sentence linked to its events.
- **P3:** storyboards and panels (four-panel scenes plus character sheets), prose sagas, and the **causal timeline**: scrub along it, click any panel or sentence through to its events and their typed causes and motives (`05.2` §4.1a).
- Every number, sentence and panel is clickable through to its provenance (A3).

## Part B — The Godot Client (**Cut, ADR-0035**)

*ADR-0035 cuts the 3D client permanently, with every custom 3D asset. This part is kept only as a record of the earlier design; nothing here will be built.*

### B1. Engine and process model
- **Godot 4.7.x** (move to 4.8 when stable, for texture streaming). MIT licence, no royalty. Forward+ on D3D12/Vulkan; a Compatibility preset for weak iGPUs.
- **Hot paths are written in Rust gdext** (`rh-godot`; MPL-2.0 binding, game code may stay closed):
  - frame decoding into `MultiMesh.buffer`;
  - the crowd LoD manager;
  - `rh-worldgen` settlement plans (shared with the server);
  - the chunk mesher;
  - WorkerW and macOS window hooks.

  GDScript is used for glue only. C# is avoided.
- **A separate process** from the simulation host. This gives crash isolation, lets the renderer pause or stop independently, and lets the client attach to a remote cluster host (R06 §8).
- **Large worlds:** origin shifting per chunk. No double-precision builds, since an on-foot area under 8 km is fine in single precision (R06 §1).

### B2. Protocol (summary; details in `05.9`)
- **JSON-RPC 2.0 is the control plane:** subscribe, inspect, Oracle verbs, dialogue turns.
- **Binary columnar frames are the state plane:**
  - a full frame every 1 s, previous-frame deltas otherwise;
  - interest management on a 25 m grid;
  - transforms at 20 Hz, rendered about 100 ms behind with interpolation;
  - **verbs plus waypoints** rather than per-frame positions.
- Godot's `WebSocketPeer` inbound buffer must be raised above 64 KB.

### B3. Street-level content pipeline (the gap in the draft)

```
seed hierarchy (counter-based)                     inputs from sim snapshot
H(ws,"region",r) → H(ws,"burg",b) → H(burg,plot)   population, wealth, era, faction, damage overrides
            │                                              │
            ▼                                              ▼
  rh-worldgen: settlement plan (05.2 §2)  ── ward plan (medieval) | tensor-field streets (modern)
            │                       incremental infill along existing roads (no global re-solve)
            ▼
  plots → building massing (shape-grammar DSL) → facade/roof/infill via WFC on GridMap (MeshLibrary kits)
            │
            ▼
  lazy interiors (room templates, stable seed per door) — only when entered
            │
            ▼
  terrain detail: upsample macro heights + seeded fBm + per-chunk erosion; rivers CARVED from macro river graph
```

- **Generators are versioned.** A content update never silently re-rolls a saved world.
- **Simulation events are overrides:** fires, demolitions and new keeps are stored as deltas over the generated baseline.
- **Acceptance test (SPK-2; from R06 Spike 2).** The same burg produces an identical 3D town on two machines. Growing it from 2k to 5k people keeps more than 90% of its buildings unchanged.

### B4. Crowd and entity LoD (R06 §5.3, R01 §R1)

| Tier | Trigger | Technique | Budget (60 FPS, mid-range GPU; validate in SPK-1) |
|---|---|---|---|
| Embodied (T3) near | ≤ 25 m, Live speed only | Skinned mesh, AnimationTree, foot IK | 20–40 |
| Embodied (T3) mid | Hydrate at 80 m; stays T3 until 130 m (hysteresis) and ≥ 10 s out of view; Live speed only | Skinned mesh, AnimationPlayer, staggered 10–20 Hz | 50–150 (≤ 200 hard cap) |
| Crowd proxies (T2c) | 80 m to 300–500 m (tuned per vantage, `05.2` §3.1) | **VAT on MultiMesh** (clip and phase in custom data; OpenVAT-style) | 1k–5k |
| Impostors | 400 m–2 km | Octahedral impostor sprites | 5k–30k |
| Aggregate | > 2 km | Density textures, lit windows, smoke, traffic streaks | Unbounded |
| Spectacle | Draw distance, at any speed band | Objects with a world-scale footprint: T1 actors (dragons) and SoA objects (armies, processions, fires), interpolated on their own clocks | Tens |

**Kitbash assignment.** Variants are assigned by **eligible-set rendezvous hashing** (R06 §8): `variant = argmax_{v ∈ Eligible(era, culture, sex, age, occupation, wealth, climate)} H(person_id, slot, v)`.
- Adding a new variant reassigns only about 1/(N+1) of people.
- Family members share face and skin slots by hashing `lineage_id`.
- Garment slots re-roll only on simulation events.
- Corruption and infection are a **shader mask parameter**, not a decal node.

### B5. Camera director (Diorama)
- Candidate vantages are pre-computed per settlement and region: market, gate, river bend, ramparts, transit hub, temple steps.
- The director scores each candidate as salience of nearby live events × visual interest (crowd density, weather, time of day) × novelty (not seen recently).
- It changes vantage on a slow cadence (minutes), with long dissolves.
- In wallpaper mode it favours **stable** shots, with occasional "event" shots: a funeral procession, a dragon overflight, a riot forming.
- Tilt-shift depth of field and a high camera produce the miniature read and hide LoD transitions.

### B6. Art bible: "painted miniature"
- Low-poly meshes.
- **One palette atlas per era**, vertex-colour AO, soft rim and outline.
- A **LUT per world and era**.
- Fog and a stylised sky.
- AreaLight3D and emissives for neon-modern worlds.
- No realistic faces.
- **Every imported asset (CC0, bought or AI-generated) goes through one re-shading pass.**

### B8. Desktop-wallpaper hosting and power policy
- **Windows:**
  - our own WorkerW host mode (send `0x052C` to Progman, find WorkerW, `SetParent`);
  - also ship a Lively application-wallpaper package.
  - Lively disables its pause rules for application wallpapers, so **Rehoboam throttles itself**.
  - Windows 11 24H2 already broke WorkerW hosting once, so keep a windowed fallback.
- **macOS:** a borderless NSWindow at desktop level that ignores the mouse and joins all Spaces, via a small Obj-C GDExtension. **Linux:** wlr-layer-shell or KDE. **GNOME:** a "picture-frame" window mode.
- **Power policy:**
  - 30 FPS cap at 0.5–0.67 render scale with FSR;
  - **0 FPS and stopped audio streams** when ≥ 95% covered or a fullscreen app is running;
  - "photograph" mode (5–10 FPS or still frames) on battery, detected by the host process because Godot has no battery API;
  - the simulation keeps running in its own process.
- **Acceptance (SPK-3; R06 Spike 3):** < 10% GPU and < 5 W extra package power at the 30 FPS cap; 0 FPS when covered.

### B9. Generative world models
Neural world models are **not** used as renderers in 2026 (VRAM, resolution, no access to simulation state, identity drift). The pattern to watch is "**engine-authoritative + neural re-render**" (Matrix-Game 4.0, released 2026-10-15): our deterministic low-poly frames would be restyled by a video model. That could become an optional premium Diorama mode once it runs at 1080p on consumer hardware. Track it in the technology radar (`07`).
