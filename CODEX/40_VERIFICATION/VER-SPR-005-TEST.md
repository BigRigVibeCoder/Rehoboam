## 3. Defects (all closed)

All reproductions start from the repository root of the stated head.

**DEF-1 (low): a `schedule-cycle` message named systems that were only downstream of the cycle.** Repro (`1e00b2b`): A reads C, B reads A, C reads B, all `same_instant`, and D reads A; the message said "A, B, C, D read each other's columns". Cause: `order_phase` returned every unvisited node. **Fixed `0687f04`** (only strongly connected components of two or more nodes are named); `a_cycle_names_only_its_members`, and mutation M40 dies.

**DEF-2 (low): the same violation was printed twice or with a self-referential text.** Repro: a plane-A system reading a plane-B column printed the `plane` line twice; a duplicate registration of `A.a` added "A.a writes a.c, which A.a also writes"; a system listing a column twice printed the same. **Fixed `bda13d3`** (each violation once; `duplicate` and `registry` are their own rules); M37 dies.

**DEF-3 (low): the ownership lint and registration disagreed on a column written twice by one system.** Repro (`1e00b2b`): an access file with `M2.demography` writing `person.alive` twice gave `0 violations` from `rh-cli ownership`, while `register()` refused the same declaration. Ruling 3 says they agree. **Fixed `c47224b`** (one shared `duplicates` rule; new control `tests/lint_fixtures/ownership/duplicate_write.access.toml` in `check_all.sh`); M38 dies.

**DEF-4 (low): the `skeletons/stale/` row in `tests/lint_fixtures/README.md` sat after the closing paragraph, outside its table.** **Fixed `c08c378`.**

**DEF-5 (low): `CLAUDE.md` listed three of the six test binaries that the `rh-core` gate runs.** **Fixed `5e1a703`.**

**DEF-6 (medium, test coverage): six plausible breakages passed the whole shipped suite and `check_all.sh` (107 PASS).** Found by the mutation matrix on `1e00b2b`: (a) a lagged read returning the current value (`world.rs`; clippy alone happened to fail my planted version); (b) `StepCtx::rng` drawing at `t = 0` instead of the instant; (c) the worker outcomes not re-sorted, so the first error depends on thread scheduling; (d) pulses stepped fine-before-coarse (the engine said coarse-first; no test and no contract); (e) a changed stub state-hash chunking (no golden of the stub hash although the sprint says the phase order is part of the hash contract); (f) `system_plane` forced to `A` (an observation system reading another observation column would be refused). **Fixed `f89c791`**: `tests/engine_contract.rs` (a serial oracle plus a case for a, b, c, d, f) and a generated golden of 120 monthly stub-world hashes (e). Re-run: every one of the six dies, and each at `Rust: unit tests (cargo nextest)` (§4). The Architect ruled that SPR-007 regenerates the golden, as a C3 change, when it replaces the hash.

**DEF-7 (medium): a `same_instant` reader could silently read a stale value when its writer ran on a finer pulse in the same phase.** Introduced by the first fix for DEF-6(d) (coarsest pulse first, ruling 1). Repro (`f89c791`): W (`Day`, `Vital`) writes `w.c`; R (`Month`, `Vital`) reads `w.c` at `same_instant`. Registration accepted it and derived the order `[W, R]`, but at a month start the engine ran R's `Month` binding before W's `Day` binding: R saw 41,760 at t = 43,200 and 84,960 at t = 86,400 (the previous day's write), against `05.1` §2 rule 4 ("the value written earlier in this instant … the owner runs first"). The same hole existed for `Hour → Day`, `Month → Season` and so on; the shipped test (d) pinned the behaviour (B ran after A's Month step and before A's Day step). **Fixed `fc635dc`** (Architect ruling): the binding `(system, pulse)` is the unit of scheduling; one dependency graph covers every binding of the phase, with edges between all bindings of a writer and a reader; levels are computed once; ties go coarser pulse first, then Registry id; two bindings of one system run in turn. Re-verified (§2 PO and CHAIN); a `cross_pulse_cycle` is refused with the right members; M42 (edges only inside one pulse, the old behaviour) dies at nextest in `edges_across_three_pulses_run_in_dependency_order` and `a_coarser_reader_sees_a_finer_writer_of_the_same_instant`.

## 6. Contract gaps

**GAP-1 (closed by ruling G-a): the code's schedule and read lags were not compared with the spec.** `SpecEntry` carried neither, so a system could bind itself to another pulse or phase, or read at another lag, than its spec says, and the scheduler would follow the code. Fixed `5d90e56` (rule `spec`). Residual (OBS-3).

**GAP-2 (closed by ruling G-b, with an approximation accepted): `start_of_day`, `previous_pulse` and `lagged` all read the start-of-instant value.** `05.1` §2 rule 4 now defines the four kinds and states the P0 approximation. The approximation is exact for the specs that exist today (S5 reads at `start_of_day` on a Day pulse). **It is not exact for `previous_pulse` (S6 and S7 bind Month and Day; "the value at the end of the instant in which the reader last fired" is not "the start of this instant") and for any `start_of_day` reader on an Hour pulse.** BCK-002 A-28 owns it. Recommendation (confidence 80%): keep A-28 ahead of P1a, and add a test that fails when a system declares `previous_pulse` or `start_of_day` before A-28 lands, so the approximation cannot be forgotten.

**GAP-3 (closed by ruling G-c): a write to a column the world lacked created it silently.** Fixed `c380a4c`.

**GAP-4 (closed by ruling G-d): `advance_until` after a step error replayed the failed instant on half-mutated tables.** Fixed `c37d6b3` (poisoning).

**GAP-5 (open, decision recorded in code only): season starts and the absence of leap years.** The code fixes seasons at months 1, 4, 7, 10 (four) and 1, 7 (two), and has no leap years; `05.1` §4.1 says neither. Recommendation (confidence 80%): put both sentences into §4.1, because a world that wants another alignment is a contract change (the `time.rs` DECISION says as much).

**GAP-6 (open, future): EventId order cannot be tested yet.** `05.1` §2 rule 4 says EventIds are assigned in the canonical order at any thread count. No events exist before SPR-006. Recommendation (confidence 90%): SPR-006 repeats the thread-count probe on event ids; I have not run it.

## 7. Observations (no action required)

- **OBS-0 (fixed `dedca52`):** `check_all.sh` hard-coded `target/debug/rh-cli`, so the parity gate failed whenever `CARGO_TARGET_DIR` was set. It now reads `$CARGO_TARGET_DIR`; round 3 ran with a fresh one.
- **OBS-1: M16 is an equivalent mutant after DEF-2.** Skipping the registration-level `plane_leak` call changes nothing, because `check_access` (the lint's own function) already reports a plane leak for any system that has a spec. The call still covers a system whose code declares a different plane from its spec. Keep it as defence in depth, or delete it (confidence 60% that it adds nothing the spec check does not).
- **OBS-2: `gen_skeletons --check` normalises line endings.** A skeleton converted to CRLF passes. Harmless to `rustc`; mentioned because the gate otherwise compares text exactly.
- **OBS-3: G-a compares lags only for reads that the spec lists, by first match.** A spec that listed one column twice with two lags would be compared with the first. `lint_odd.py` refuses duplicate `[[reads]]`, so this cannot occur through the real specs.
- **OBS-4: registration accepts odd names when the spec agrees** (an empty id, an empty or dotless column, ` A `). The spec lint is the guard (GOV-003 asks for validation at public boundaries; the table is built from validated specs). A system with no binding is accepted if its spec has none.
- **OBS-5: `Engine::new` accepts a world that already contains a column no system declares**, and hashes it. Intended for the stub world; revisit when typed tables arrive.
- **OBS-6: a `same_instant` read of a column that a system writes in two phases** is refused if either phase is later than the reader's. Conservative and consistent with rule 4.
- The stub `state_hash` is SplitMix64 over `i64` columns (the sprint says so); it cannot reveal cross-machine differences of a real hash. SPR-007 owns that.
